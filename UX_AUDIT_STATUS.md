# Исправления UX-аудита: UX-03 — UX-11

## Реализовано во фронтенде

- UX-03: поиск, город, категория, активные условия и сброс доступны прямо в афише главной страницы.
- UX-04: посещение сайта не вызывает запрос геолокации. Поиск рядом запускается явным действием; при ошибке доступен переход к выбору города на карте.
- UX-05: самостоятельное участие восстанавливается из серверного списка своих событий с `relation`, с исключением участия через компании. Отмена доступна в деталях события и в личном кабинете.
- UX-06: парольный вход не меняет текущий раздел и выбранное событие. Значимые действия после входа не выполняются автоматически. Для OAuth сохраняются адрес возврата и идентификатор события.
- UX-07: повторный просмотр возвращает все карточки; сохранённое избранное сохраняется, в том числе после пропуска и отмены действия при пересмотре.
- UX-08: основные модальные окна используют общий перевод/удержание/возврат фокуса и Escape. Формы создания и регистрации предупреждают о потере введённых данных и не закрываются во время сохранения. Календарь и select обрабатывают свой Escape отдельно.
- UX-09: лента распределяет доступную высоту между карточкой и действиями; фильтры карты сворачиваются на мобильных экранах. Текущие основные действия остаются в обычном порядке клавиатурного обхода.
- UX-10: после изменения участия и компаний событие перечитывается с сервера; обновляются выбранное событие, фоновый каталог и данные личного кабинета. Устаревшие ответы загрузки личного кабинета игнорируются.
- UX-11, фронтенд: общая функция склонения проверена на 0, 1, 2, 5, 11, 21. Явные технические справочники (`Map test city`, `Map test category`, префиксы e2e/fixture) и связанные с ними события исключены из публичной выдачи. Реальные пользовательские записи не подменяются вымышленными событиями.

## Осталось на стороне данных и проверки

1. UX-11: очистить и изолировать тестовые записи в серверной demo-базе и наполнить её реалистичными событиями. Фронтенд-фильтрация — защитная мера, не замена серверной изоляции. Записи с обычными названиями и справочниками невозможно надёжно признать тестовыми без серверного признака; такие записи автоматически не удаляются и не скрываются.
2. Отдельно проверить реальные экраны 360×732, desktop 1440×1000, открытие экранной клавиатуры и скринридер. Браузерная проверка не выполнялась по договорённости с пользователем; автоматические проверки покрывают логику, а не фактическую геометрию браузера.
3. Новых основных API не требуется. Использованы существующие `GET /users/me/events`, `GET /users/me/companies`, `GET /events/{id}`, `POST/DELETE /events/{id}/solo-participation`.
