# Кофе-тайм: первая версия

Маршрут интерфейса: `/#coffee`. Вход через вкладку «Кофе-тайм» в разделе карты. Верхний переключатель «События / Кофе-тайм» отображается только на карте и в кофе-тайме, на всех размерах экрана. «События» возвращает на `/#map`. Кнопки в главном баннере и отдельного пункта основного меню нет. Нижняя мобильная навигация сохраняет пять основных пунктов.

## Что реализовано

- Каталог встреч с фильтрами по городу, настроению, дате и свободным местам; раздел «Я участвую».
- Создание встречи: название, описание, город, место, необязательный адрес, дата/время, 30/60/90/120 минут, 2–8 участников вместе с организатором, свободный вход или заявки.
- Детали встречи, вступление/выход, отправка/отмена заявки, состояния заполненной/закрытой/завершённой встречи.
- Связь с существующими событиями, компаниями, личным кабинетом и чатами. Одобрение заявок и управление набором — существующий раздел «Мои компании» в личном кабинете.
- Демо-реализация сохраняет данные в существующем хранилище, добавляет шесть встреч без сброса пользовательских событий и избранного.

## Статус серверной интеграции

**Ниже — новый контракт, который ещё необходимо реализовать на бэкенде.** Адаптер фронтенда подготовлен, но само наличие методов в нём не подтверждает наличие серверных маршрутов. В режиме `VITE_API_MODE=backend` нет автоматической подмены ответов моками: при 404 раздел показывает, что API ещё не подключено. Рабочая реализация сейчас — в демо-режиме.

### Новые маршруты `/api/v1`

1. `GET /coffee-meetings?cityId=1&topic=chat&page=1&limit=50`
   - Публичный список актуальных встреч; у авторизованного пользователя учитывать его участие.
   - Необязательные `cityId`, `topic` (`chat`, `work`, `walk`).
   - Ответ `Paginated<CoffeeMeeting>`: `items` и стандартный `pagination` (`page`, `limit`, `total`, `totalPages`). Фронтенд запрашивает все страницы.
   - Публично выдавать активные события с незаблокированной компанией и будущим окончанием. Организатору дополнительно возвращать его встречи, ожидающие модерации.
2. `GET /coffee-meetings/{id}` → `CoffeeMeeting` с актуальным состоянием участия. Недоступную/заблокированную встречу не раскрывать посторонним.
3. `POST /coffee-meetings` → `CoffeeMeeting`; необходим авторизованный пользователь с заполненным профилем.
   - **Одна транзакция** создаёт событие, компанию, запись кофе-тайма и членство организатора. Нельзя оставлять отдельное событие без компании при частичной ошибке.
   - Запрос соответствует `CoffeeInput` из `src/api/coffeeTypes.ts`. `startsAt` — ISO с часовым поясом; окончание вычисляется сервером из `duration`.
   - Организатор занимает одно из `maxMembers` мест. Компания привязана к событию; напитки участники оплачивают самостоятельно.
   - Сервер определяет статус публикации по существующим правилам модерации. UI поддерживает `pending`: встреча отображается у автора, вступление до публикации запрещено. Демо создаёт активные встречи для проверки сценария.
   - Установить согласованный механизм idempotency для повторных сетевых запросов; клиент блокирует двойное нажатие, но это не заменяет серверную защиту.

### Ответ `CoffeeMeeting`

```ts
{
  id: number;
  eventId: number;
  companyId: number;
  topic: "chat" | "work" | "walk";
  event: Event;       // существующая структура события
  company: Company;   // существующая структура компании
  participation: "none" | "owner" | "member" | "pending";
}
```

`participation` вычисляется сервером для текущего пользователя; для гостя — `none`. Счётчики отражают реальный состав компании, включая организатора. Ответы с персональным участием нельзя кэшировать между пользователями.

### Переиспользуемые маршруты

- `POST /companies/{id}/join` — свободное вступление.
- `DELETE /companies/{id}/members/me` — выйти из встречи; организатору выход запрещён, он управляет компанией из личного кабинета.
- `POST /companies/{id}/applications`, `DELETE /companies/{id}/applications/me` — отправить/отменить заявку.
- Существующее одобрение/отклонение заявок, открытие/закрытие набора, сообщения компании и WebSocket-чаты.
- `/users/me/events` и `/users/me/companies` должны включать связанные встречи и компании; доступ к чату предоставляется только после вступления/одобрения.

Все операции вступления и одобрения должны атомарно проверять статус и окончание встречи, набор, лимит мест и повторное членство. Заявка до одобрения не занимает место. Выход и одобрение обновляют счётчики события и компании. Для восстановления UI после конфликтов возвращать стандартный `ApiError` и актуальные данные через GET.

Обычный каталог событий в демо не дублирует кофе-встречи: они доступны в своём разделе и в личных планах участников. Такое же разделение требуется согласовать для серверного каталога.

## Проверка

Покрыты: валидация, пагинация, сохранение и миграция, создание без частичных данных, места/дубли/завершённые встречи, заявки/одобрение/отмена, связь с существующими компаниями и чатами, гостевой вход и состояния кнопок, CSS-брейкпоинты 320–1440px. Проверка в браузере и на физическом iPhone не выполнялась по договорённости с пользователем.
